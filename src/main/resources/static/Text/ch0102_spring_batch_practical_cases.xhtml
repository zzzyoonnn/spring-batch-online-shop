2.1 의존성 구성 (Maven)

마켓온은 Maven으로 빌드합니다. pom.xml의 부모로 Spring Boot 3.x 스타터를 두고, 다음 스타터·라이브러리를 추가합니다. (구체적인 버전은 [start.spring.io](https://start.spring.io)에서 생성하면 호환되는 최신 안정 버전이 자동으로 채워집니다. 버전 숫자는 공식 문서·스타터로 확인하세요.)

<dependencies>
    <!-- 웹 + 화면 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-thymeleaf</artifactId>
    </dependency>

    <!-- 배치 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-batch</artifactId>
    </dependency>

    <!-- 데이터 접근 + MySQL -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>

    <!-- 보안 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-security</artifactId>
    </dependency>

    <!-- 검증 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

    <!-- Lombok -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
</dependencies>

💡 Tailwind CSS는 CDN으로 불러올 것이므로 별도 의존성이 없습니다. 4장에서 HTML <head>에 한 줄만 추가합니다. 빌드 도구도 필요 없습니다.

2.2 MySQL과 application.properties

마켓온은 MySQL 하나에 업무 데이터(상품·주문·회원·정산 등)와 배치 메타데이터(Job 실행 이력)를 함께 둡니다. 먼저 데이터베이스를 만듭니다.

CREATE DATABASE marketon DEFAULT CHARACTER SET utf8mb4;

src/main/resources/application.properties를 다음과 같이 작성합니다.

# --- DataSource ---
spring.datasource.url=jdbc:mysql://localhost:3306/marketon?serverTimezone=Asia/Seoul&characterEncoding=UTF-8
spring.datasource.username=marketon
spring.datasource.password=changeme
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

# --- JPA ---
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

# --- Spring Batch ---
# 메타테이블 자동 생성 (개발용). 운영에서는 수동 생성 후 never 권장
spring.batch.jdbc.initialize-schema=always
# 애플리케이션 기동 시 등록된 Job을 자동 실행하지 않음 (우리는 화면에서 직접 실행)
spring.batch.job.enabled=false

⚠️ spring.batch.job.enabled=false는 이 책에서 중요합니다. 기본값이면 애플리케이션이 뜰 때마다 등록된 Job이 멋대로 한 번씩 실행됩니다. 우리는 관리자 화면에서 원하는 때에 실행할 것이므로 자동 실행을 꺼 둡니다.

📌 핵심: 업무 DB와 배치 메타 DB가 같은 데이터소스를 쓰면, 배치 작업과 메타데이터 기록이 한 트랜잭션 흐름 안에서 일관되게 동작합니다.

2.3 메타테이블이 만들어지는 원리

Spring Batch는 Job·Step의 실행 상태를 6개 안팎의 메타테이블에 기록합니다.

BATCH_JOB_INSTANCE       어떤 Job이 어떤 파라미터로 정의됐는가
BATCH_JOB_EXECUTION      그 Job 실행의 성공/실패/시각
BATCH_JOB_EXECUTION_PARAMS  실행에 넘긴 파라미터
BATCH_STEP_EXECUTION     각 Step의 읽기/쓰기/스킵 건수와 상태
BATCH_JOB_EXECUTION_CONTEXT / BATCH_STEP_EXECUTION_CONTEXT  재시작용 상태 저장

위 initialize-schema=always 설정 덕분에, 애플리케이션을 처음 띄우면 Spring Batch가 MySQL용 스키마 스크립트(org/springframework/batch/core/schema-mysql.sql)를 실행해 이 테이블들을 자동으로 만들어 줍니다. 메타테이블의 의미는 3장과 17장에서 자세히 다루고, 빠른 참조는 부록 A에 정리했습니다.

💡 운영 환경에서는 권한 분리와 안정성을 위해 스키마를 사람이 직접 만들고 spring.batch.jdbc.initialize-schema=never로 두는 것이 일반적입니다. 스크립트는 spring-batch-core JAR 안에 DB 종류별로 들어 있습니다.

2.4 프로젝트 패키지 구조

사례가 늘어도 흐트러지지 않도록, 처음부터 패키지를 사례 단위로 나눕니다.

com.marketon
├─ MarketOnApplication.java     // main
├─ common/                      // 공통 설정 (보안, 시간 등)
├─ admin/                       // 관리자 화면 컨트롤러·뷰
└─ batch/
   ├─ product/                  // 5장 CSV 업로드
   ├─ settlement/               // 7장 정산
   ├─ dormant/                  // 9장 휴면 전환
   └─ ...                       // 사례별 Job·Step·Reader/Writer

각 사례 패키지에는 그 배치의 *JobConfig, 도메인 엔티티, Reader/Processor/Writer가 함께 들어갑니다. 한 사례를 이해하려면 한 패키지만 보면 되도록 응집도를 높이는 것이 목적입니다.

🧪 실습 — 프로젝트 띄우기

  1. [start.spring.io](https://start.spring.io)에서 위 의존성으로 Maven 프로젝트를 생성합니다.
  2. 로컬 MySQL에 marketon 데이터베이스와 계정을 만듭니다.
  3. application.properties를 2.2처럼 작성하고 애플리케이션을 실행합니다.
  4. MySQL에서 SHOW TABLES LIKE 'BATCH_%';를 실행해 메타테이블 6개가 생겼는지 확인합니다.

메타테이블이 보이면 배치를 돌릴 토대가 완성된 것입니다.

이 장의 요점

  • 마켓온은 Maven + Spring Boot 3.x로 빌드하고, 웹·Thymeleaf·Batch·JPA·Security·Validation·Lombok 의존성을 씁니다.
  • application.properties에서 MySQL을 연결하고, spring.batch.job.enabled=false로 자동 실행을 끄고, initialize-schema=always로 메타테이블을 자동 생성합니다.
  • 배치 메타테이블은 Job/Step 실행 이력을 기록하며, 재시작과 운영 추적의 근거가 됩니다.
