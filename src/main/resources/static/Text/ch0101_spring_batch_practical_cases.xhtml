1장. Spring Batch는 언제 쓰는가

이 장에서 배우는 것

  • 배치 작업이란 무엇이고, 어떤 업무가 여기에 해당하는지
  • Spring Batch가 적합한 경우와 굳이 쓰지 않아도 되는 경우를 구분하는 기준
  • 이 책에서 함께 만들 마켓온(MarketOn)과 10가지 사례 지도

1.1 배치란 무엇인가

배치(batch)는 "한 묶음"이라는 뜻입니다. 사용자의 요청에 즉시 한 건씩 반응하는 온라인 처리와 달리, 대량의 데이터를 한 묶음으로 모아 정해진 규칙에 따라 읽고, 가공하고, 저장하거나 전달하는 작업을 가리킵니다. 핵심 단어는 세 가지입니다. 대량, 정해진 규칙, 자동 실행.

쇼핑몰을 예로 들어 보겠습니다. 고객이 결제 버튼을 누르면 그 자리에서 즉시 응답해야 합니다. 이건 온라인 처리입니다. 반면 "어제 하루 동안 발생한 모든 주문을 모아 판매자별로 정산 금액을 계산해 두는 일"은 지금 당장 누가 기다리지 않습니다. 새벽에 한 번 몰아서 처리하면 됩니다. 이런 일이 배치입니다.

📌 핵심: 사람이 실시간으로 기다리지 않고, 대량 데이터를 규칙에 따라 한꺼번에 처리하는 자동화 작업이 배치입니다.

배치 작업은 보통 다음과 같은 주기로 돌아갑니다.

매시간   — 외부 API에서 배송 상태 수집
매일 새벽 — 정산, 통계 집계, 휴면 회원 전환
매월     — 월별 리포트 생성, 오래된 데이터 아카이빙
필요 시   — 관리자가 올린 CSV 대량 업로드

1.2 Spring Batch가 적합한 경우

Spring Batch는 Reader → Processor → Writer 구조의 Chunk 기반 처리를 중심으로, 실패 시 재시도(Retry), 건너뛰기(Skip), 재시작(Restart), 병렬 처리 같은 기능을 제공하는 프레임워크입니다. 다음 조건이 많이 해당될수록 Spring Batch가 잘 맞습니다.

대량 데이터를 처리한다
정해진 시간에 반복 실행한다
실패 시 어디서부터 다시 시작할지가 중요하다
처리 이력을 남겨야 한다
트랜잭션 단위(몇 건씩 커밋)를 제어해야 한다
외부 API·파일·DB를 함께 다룬다
일부 실패 데이터를 건너뛸지 말지 결정해야 한다
작업을 여러 단계(Step)로 나누고 싶다

이유는 간단합니다. 대량 작업은 반드시 중간에 실패합니다. 네트워크가 끊기고, 잘못된 CSV 행이 섞여 있고, DB 제약조건에 걸립니다. 이때 "처음부터 전부 다시"는 답이 아닙니다. Spring Batch는 어디까지 처리했는지를 JobRepository라는 메타 저장소에 기록하므로, 실패한 지점부터 다시 시작할 수 있습니다.

💡 공식 문서도 대용량 배치에서는 먼저 단순한 단일 스레드 방식으로 성능을 측정한 뒤, 필요할 때 멀티스레드·파티셔닝 같은 확장을 고려하라고 권합니다. 처음부터 복잡하게 만들 필요는 없습니다.

1.3 굳이 Spring Batch를 쓰지 않아도 되는 경우

반대로, 모든 반복 작업에 Spring Batch가 필요한 것은 아닙니다. 다음과 같은 경우에는 오히려 과합니다.

단순히 매분 API 하나를 호출하는 정도
데이터가 몇 건 안 됨
실패해도 재처리가 중요하지 않음
복잡한 상태 관리가 필요 없음
실시간 처리가 더 중요함

이럴 때는 스프링이 기본 제공하는 @Scheduled만으로 충분합니다.

@Scheduled(cron = "0 0 2 * * *") // 매일 새벽 2시
public void runSimpleTask() {
    // 간단한 작업
}

하지만 작업이 커지고 이력 관리·재시작·Chunk 처리·Skip/Retry가 필요해지는 순간, @Scheduled 안의 코드는 급격히 복잡해집니다. 그 임계점을 넘으면 Spring Batch로 전환하는 것이 낫습니다.

⚠️ "스케줄러가 곧 배치"라는 오해를 조심하세요. @Scheduled는 언제 실행할지를 정하는 도구일 뿐입니다. 어떻게 안전하게 대량 처리할지를 책임지는 것이 Spring Batch입니다. 17장에서 둘을 함께 씁니다.

1.4 우리가 만들 것: 마켓온과 10가지 사례

이 책은 가상의 쇼핑몰 마켓온(MarketOn)의 운영 백오피스를 함께 만듭니다. 관리자가 로그인해 들어가는 화면이 있고(4장), 그 화면의 버튼들이 아래 사례별 배치를 실행합니다.

 5장  상품 CSV 대량 업로드        파일 → 검증 → DB
 6장  DB 마이그레이션·데이터 보정    DB → 변환 → DB
 7장  매일 새벽 정산              주문 → 수수료 계산 → 정산 테이블
 8장  통계·리포트 집계            원장 → 집계 → 통계 테이블
 9장  휴면 회원 전환              회원 → 상태 변경 + 알림 대상
10장  알림 발송 대상 생성          조건 추출 → notification_target
11장  로그·이벤트 후처리          raw 로그 → 요약 테이블
12장  만료·삭제·아카이빙          오래된 데이터 → 아카이브/삭제
13장  외부 API 데이터 수집         API → 변환 → DB (Retry)
14장  검색 인덱스 동기화          DB → 검색 엔진 (전체/증분)

각 사례는 독립적으로 읽어도 되지만, 같은 프로젝트 위에 쌓이도록 설계했습니다. 1부(1~4장)에서 토대를 닦고, 2~4부에서 사례를 구현하고, 5부에서 Skip/Retry·확장·운영을 마무리합니다.

이 장의 요점

  • 배치는 대량 데이터를 규칙에 따라 자동으로 한꺼번에 처리하는 작업이며, 실시간 응답이 필요 없는 업무에 적합합니다.
  • 대량·반복·재시작·이력·트랜잭션 제어가 필요하면 Spring Batch, 단순 반복이면 @Scheduled로 충분합니다.
  • 이 책은 마켓온 운영 백오피스를 만들며 10가지 실전 사례를 한 프로젝트에서 구현합니다.
