4장. 운영 관리자 화면 만들기

이 장에서 배우는 것

  • Spring Security로 관리자만 들어오는 백오피스 보호하기
  • Thymeleaf + Tailwind(CDN)로 배치 실행·이력 조회 화면 그리기
  • JobLauncher로 화면 버튼에서 배치를 실행하고, 메타테이블을 읽어 이력 보여 주기

4.1 왜 화면이 먼저인가

배치는 보이지 않는 곳에서 돌기 때문에, 실행하고 상태를 확인할 창구가 없으면 운영이 막막합니다. 그래서 사례를 구현하기 전에 운영 콘솔부터 만듭니다. 이 화면은 책 전체에서 계속 자라납니다. 5장에서 CSV 업로드 버튼이, 7장에서 정산 실행 버튼이 여기 붙습니다.

📌 핵심: 배치 시스템에서 화면은 사치가 아니라 운영 도구입니다. "실행" 버튼과 "이력" 표 두 가지면 충분히 시작할 수 있습니다.

4.2 Spring Security로 백오피스 잠그기

운영 배치는 정산·회원·삭제처럼 위험한 작업을 다루므로, 인증된 관리자만 접근해야 합니다. 가장 단순한 형태로 시작합니다.

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/css/**", "/js/**").permitAll()
                .anyRequest().hasRole("ADMIN"))
            .formLogin(form -> form
                .loginPage("/login").permitAll());
        return http;
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return PasswordEncoderFactories.createDelegatingPasswordEncoder();
    }

    @Bean
    public UserDetailsService users(PasswordEncoder encoder) {
        UserDetails admin = User.withUsername("admin")
                .password(encoder.encode("admin1234"))
                .roles("ADMIN")
                .build();
        return new InMemoryUserDetailsManager(admin);
    }
}

여기서는 학습을 위해 관리자 계정을 메모리에 둡니다. 실제 서비스라면 회원 테이블과 UserDetailsService를 연결하고 비밀번호를 BCrypt로 저장합니다.

⚠️ 배치를 실행하는 엔드포인트(POST /admin/jobs/...)는 반드시 인증·권한 확인 뒤에 두어야 합니다. 외부에서 정산이나 삭제 배치를 임의로 트리거할 수 있으면 큰 사고로 이어집니다. CSRF 보호도 켜 두세요(폼에 토큰 자동 삽입).

4.3 Thymeleaf + Tailwind로 대시보드 그리기

Tailwind는 CDN으로 한 줄만 추가하면 됩니다. 빌드 과정이 없어 학습용 백오피스에 잘 맞습니다.

src/main/resources/templates/admin/dashboard.html:

<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
  <meta charset="UTF-8">
  <title>마켓온 운영 콘솔</title>
  <script src="https://cdn.tailwindcss.com"></script>
</head>
<body class="bg-gray-50 p-8">
  <h1 class="text-2xl font-bold mb-6">마켓온 운영 콘솔</h1>

  <!-- 배치 실행 카드 -->
  <div class="bg-white rounded-xl shadow p-6 mb-8">
    <h2 class="text-lg font-semibold mb-4">배치 실행</h2>
    <form th:action="@{/admin/jobs/hello}" method="post">
      <button class="px-4 py-2 rounded-lg bg-indigo-600 text-white">
        Hello 배치 실행
      </button>
    </form>
  </div>

  <!-- 실행 이력 표 -->
  <div class="bg-white rounded-xl shadow p-6">
    <h2 class="text-lg font-semibold mb-4">최근 실행 이력</h2>
    <table class="w-full text-sm">
      <thead class="text-left text-gray-500 border-b">
        <tr><th class="py-2">Job</th><th>상태</th><th>시작</th><th>종료</th></tr>
      </thead>
      <tbody>
        <tr th:each="e : ${executions}" class="border-b">
          <td class="py-2" th:text="${e.jobName}">jobName</td>
          <td>
            <span th:text="${e.status}"
                  th:classappend="${e.status.name() == 'COMPLETED'}
                    ? 'text-green-600' : 'text-red-600'">STATUS</span>
          </td>
          <td th:text="${e.startTime}">start</td>
          <td th:text="${e.endTime}">end</td>
        </tr>
      </tbody>
    </table>
  </div>
</body>
</html>

💡 th:classappend로 상태값에 따라 색을 바꾸면, 실패한 실행이 표에서 빨갛게 도드라져 한눈에 들어옵니다. 운영 화면의 작은 친절이 장애 대응 속도를 바꿉니다.

4.4 화면에서 배치 실행하기

이제 버튼을 실제 배치에 연결합니다. 핵심은 JobLauncher입니다. Job과 JobParameters를 넘기면 실행해 줍니다.

@Controller
@RequestMapping("/admin")
@RequiredArgsConstructor
public class AdminBatchController {

    private final JobLauncher jobLauncher;
    private final Job helloJob;
    private final JobExplorer jobExplorer; // 이력 조회용

    @GetMapping
    public String dashboard(Model model) {
        // 최근 실행 이력을 화면에 전달 (간략화)
        model.addAttribute("executions", recentExecutions());
        return "admin/dashboard";
    }

    @PostMapping("/jobs/hello")
    public String runHello() throws Exception {
        JobParameters params = new JobParametersBuilder()
                .addLong("runAt", System.currentTimeMillis()) // 매번 다른 파라미터
                .toJobParameters();
        jobLauncher.run(helloJob, params);
        return "redirect:/admin";
    }
}

여기서 runAt에 현재 시각을 넣은 이유가 중요합니다. Spring Batch는 같은 Job + 같은 파라미터 조합을 한 번만 성공 실행하도록 막습니다(JobInstanceAlreadyCompleteException). 그래서 "언제든 다시 눌러도 실행되는" 단순 작업에는 매번 다른 값을 넣습니다.

⚠️ 반대로 정산·통계처럼 기준일 하루에 한 번만 돌아야 하는 배치는 이 동작이 오히려 안전장치가 됩니다(7·8장). 파라미터에 date=2026-06-29를 넣으면, 같은 날짜로는 두 번 성공 실행되지 않습니다. 파라미터 설계가 곧 멱등성 설계의 출발점입니다.

4.5 이력 조회

이력은 메타테이블을 읽는 JobExplorer로 가져옵니다. JPA로 직접 조회하지 않고 Spring Batch가 제공하는 API를 쓰면, 메타 스키마가 바뀌어도 코드가 안전합니다.

💡 버전 메모 — Spring Batch 6에서는 JobRepository가 JobExplorer를 상속하도록 바뀌어, 별도의 JobExplorer 빈이 필요 없어졌습니다(JobExplorer 자체는 deprecated). 6에서는 아래 코드의 jobExplorer 자리에 JobRepository를 주입해 같은 메서드(getJobNames, getJobInstances, getJobExecutions)를 그대로 호출하면 됩니다. 마찬가지로 JobOperator가 JobLauncher를 상속하므로, 실행도 JobOperator 하나로 통합할 수 있습니다. 동작과 메서드 이름은 동일하므로 이 책의 흐름은 그대로 적용됩니다.

private List<JobExecution> recentExecutions() {
    List<JobExecution> result = new ArrayList<>();
    for (String name : jobExplorer.getJobNames()) {
        jobExplorer.getJobInstances(name, 0, 5).forEach(instance ->
            result.addAll(jobExplorer.getJobExecutions(instance)));
    }
    return result;
}

🧪 실습 — 운영 콘솔 완성하기

  1. SecurityConfig, dashboard.html, AdminBatchController를 추가합니다.
  2. 애플리케이션을 띄우고 /login에서 admin / admin1234로 로그인합니다.
  3. "Hello 배치 실행" 버튼을 누르고, 아래 이력 표에 COMPLETED 행이 초록색으로 뜨는지 확인합니다.
  4. 버튼을 여러 번 눌러 매번 새 실행이 쌓이는지 봅니다(runAt 덕분).

이 콘솔이 앞으로 모든 사례 배치의 실행·확인 창구가 됩니다.

이 장의 요점

  • 배치를 만들기 전에 운영 콘솔을 먼저 세웁니다. Spring Security로 관리자만 접근하게 잠급니다.
  • Thymeleaf + Tailwind(CDN)로 "실행 버튼"과 "이력 표"를 그리고, 상태값에 따라 색을 달리해 가독성을 높입니다.
  • 화면 버튼은 JobLauncher.run(job, params)로 배치를 실행하고, 이력은 JobExplorer로 메타테이블에서 읽습니다. JobParameters 설계가 멱등성의 출발점입니다.

다음 장에서는 첫 실전 사례로 들어갑니다. 관리자가 올린 상품 CSV 10만 건을 한 줄씩 읽고 검증해 저장하고, 실패한 행만 따로 리포트로 남기는 업로드 배치를 만듭니다.
