부록 A. Spring Batch 메타테이블 빠른 참조

Spring Batch는 Job·Step의 실행 상태를 메타테이블에 기록합니다. 이 테이블들이 재시작·이력 추적·멱등성의 근거가 됩니다. (처음 자세히 다룬 장: 2장·17장)

메타테이블 한눈에 보기

테이블무엇을 담는가자주 보는 컬럼
BATCH_JOB_INSTANCEJob + 파라미터 조합(논리적 실행 단위)job_instance_id, job_name
BATCH_JOB_EXECUTION한 번의 Job 실행 결과status, start_time, end_time, exit_message
BATCH_JOB_EXECUTION_PARAMS실행에 넘긴 파라미터parameter_name, parameter_value
BATCH_STEP_EXECUTIONStep별 실행 결과·건수read_count, write_count, skip_count, commit_count, status
BATCH_JOB_EXECUTION_CONTEXTJob 실행 상태(재시작용)serialized_context
BATCH_STEP_EXECUTION_CONTEXTStep 실행 상태(어디까지 읽었나)serialized_context

컬럼명은 Spring Batch 버전에 따라 일부 다를 수 있습니다(예: 시퀀스 테이블 유무). 정확한 스키마는 사용하는 버전의 공식 스키마 스크립트(org/springframework/batch/core/schema-*.sql)로 확인하세요.

상태값(BatchStatus / ExitStatus)

상태의미
STARTING / STARTED시작 준비 / 실행 중
COMPLETED정상 종료
FAILED실패 (재시작 대상)
STOPPED중지됨
ABANDONED포기됨 (재시작 시 건너뜀)

운영에서 자주 쓰는 조회

-- 최근 실행 이력
SELECT job_execution_id, job_instance_id, status, start_time, end_time
FROM BATCH_JOB_EXECUTION
ORDER BY job_execution_id DESC LIMIT 20;

-- 실패한 실행과 원인
SELECT e.job_execution_id, i.job_name, e.status, e.exit_message
FROM BATCH_JOB_EXECUTION e
JOIN BATCH_JOB_INSTANCE i ON e.job_instance_id = i.job_instance_id
WHERE e.status = 'FAILED'
ORDER BY e.job_execution_id DESC;

-- Step별 처리 건수
SELECT step_name, read_count, write_count, skip_count, commit_count, status
FROM BATCH_STEP_EXECUTION
WHERE job_execution_id = ?;

스키마 초기화 설정 (application.properties)

# 개발: 자동 생성 / 운영: 수동 생성 후 never 권장
spring.batch.jdbc.initialize-schema=always   # always | embedded | never
# 기동 시 등록된 Job 자동 실행 여부 (이 책은 화면/스케줄러로 실행하므로 false)
spring.batch.job.enabled=false

💡 메타테이블은 코드로 직접 조회하기보다 JobExplorer·JobOperator API로 다루면 버전 변화에 안전합니다(4장·17장).

💡 버전 메모(Spring Batch 6) — 6.0부터 JobRepository가 JobExplorer를, JobOperator가 JobLauncher를 상속합니다. 따라서 별도의 JobExplorer·JobLauncher 빈 없이 JobRepository·JobOperator만으로 조회와 실행을 모두 처리할 수 있습니다(JobExplorer는 deprecated). 메서드 이름과 동작은 동일하므로 이 책 예제는 5.2 이상과 6.0에서 그대로 동작합니다.
